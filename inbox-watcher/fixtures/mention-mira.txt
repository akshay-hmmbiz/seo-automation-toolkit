Page titles and descriptions
Heading order

Redirect chains
Missing image text
Slow pages
Sitemap and robots file
Pages that cannot be indexed
Duplicate pages
Structured data
Internal links
Missing or repeated elements
Mobile layout problems
Proofreading (spelling and grammar)
Content that disagrees between pages
leftover scripts that are no longer needed
Blog gaps
The goal is to have the different checkers do this work on their own and
then put everything into one report, rather than keeping many separate
sheets. The final report should be laid out so it is easy for developers to
read and act on. Ideally, each problem should include: Problem → Why it
matters → Affected pages → Priority → Suggested fix → Technical notes
This will make it much easier for the development team to review the
findings, decide what comes first, and make the changes. In short, we need
a Page Check Tool that runs the whole review and writes one clear report in
one place.

**What the tool should do** Build the weekly report from several data
sources, for four kinds of report: 1. Traffic summary 2. Enquiry summary 3.
Page speed summary 4. Content calendar and other planning notes First step
should be choosing which kind of report we want to run. Based on that
choice it asks for the relevant inputs. **Inputs it should ask (common to
all types)**

Which website the report is for
Which week or date range to cover
Who the report should be addressed to
Which numbers to leave out, if any
Whether we already have a template — if yes, use ours; if no, it picks
a sensible layout itself for that kind of report
**Type-specific inputs**

Traffic summary: which pages to highlight, and what to compare against
Enquiry summary: which forms to count, plus the opening hours of the
business (name, address, phone, category, hours, description) — these must
match exactly with what is on the live site
Page speed summary: which page or group of pages to test
**Process expectations**

It should collect the numbers from each source by itself using the access
that has been set up
If it cannot reach a source, it should pause and hand over to the user
(human) to sort it out, then continue from there
Keep a record of which source each number came from
**Output — this part is important**

Return the finished report for every website asked for (checked, not
just "generated")
For any report that failed, return the actual reason with detail — not
a generic error. For example: source not reachable, access expired, date
range has no data, template missing a section, etc.
**Content requirement** All wording must be fresh and relevant every time
— no copy and paste from last week's report.

Traffic and enquiry summaries: title, notes and wording should be
relevant to the website asked for
Page speed summary: written around the pages tested, reading like a
short note from a colleague
Planning notes: wording and details written according to the website and
the plan already shared
